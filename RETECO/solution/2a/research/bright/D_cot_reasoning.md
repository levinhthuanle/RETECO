# D: Chain-of-Thought & RL-Based Reasoning for Retrieval

## Tại sao CoT Matters for Retrieval

Standard retrieval: `embed(query)` → nearest neighbor
CoT retrieval: `reason(query)` → `embed(query + reasoning)` → nearest neighbor

CoT bridges the semantic gap on BRIGHT because:
1. LLM reasons through what information is actually needed
2. Reasoning uses terminology closer to documents than the original query
3. Multiple reasoning steps can uncover multi-hop information needs

---

## Search-R1: RL for Reasoning-Intensive Retrieval (2025)

**Paper:** "Search-R1: Training LLMs to Reason and Retrieve" (2025)
- arXiv: 2503.09516
- Authors: Jin, Zhu, Tian, Liu, et al.

**Core idea:** Train LLM end-to-end to interleave search and reasoning:
```
<think>To answer X, I need to search for Y</think>
<search>Y</search>
<result>...documents...</result>
<think>Given Y, I also need Z</think>
<search>Z</search>
<answer>...</answer>
```

RL reward: final answer correctness (not intermediate retrieval quality)

**Key innovation:** Model learns WHEN to search and WHAT to search for, through reward from final answer, not explicit supervision on search queries.

**Results:** 
- Significantly outperforms non-RL baselines on BRIGHT (absolute numbers not in abstract)
- Demonstrates that RL can teach implicit reasoning for retrieval

**Relevance to RECOR:** HIGH concept-wise, but requires training. The key insight — generate reasoning first, then query — can be applied WITHOUT training by using LLM prompting (the H+R strategy in RECOR paper is essentially the inference-time version of this).

## ReasonIR: Retriever Trained on Synthetic Reasoning Data (Meta AI, 2025)

**Paper:** "ReasonIR: Training Reasoners for Dense Retrieval" 
- arXiv: 2504.20595
- Authors: Shi, Wang, Shi, Chang, Yih, Karpukhin, et al. (Meta AI + MIT)

### Training Pipeline

**Step 1: Reasoning data synthesis**
- Start from various QA datasets (MMLU, GPQA, TheoremQA, etc.)
- Use GPT-4 to generate (query → reasoning_chain → relevant_document) triplets
- Hard negative mining: retrieve plausible but wrong documents
- Scale: ~100K reasoning-rich training triplets

**Step 2: Multi-stage fine-tuning**
- Start: Llama-3-8B
- Stage 1: Contrastive learning on reasoning triplets
- Stage 2: Hard negative training
- Result: ReasonIR-8B

**Step 3: Inference**
At inference, ReasonIR uses the same query format as RECOR's "Reasoning" strategy:
```
Query: {question}
Let me think step by step: {reasoning_chain}  ← generated by separate LLM
```

### Performance

| Setting | nDCG@10 |
|---------|---------|
| BRIGHT alone | 29.9 |
| BRIGHT + Qwen reranker | 36.9 |
| RECOR H+R strategy | 0.552 macro |

### Why ReasonIR works:
The model's embedding space is aligned with *reasoning paths*, not just surface semantics. When you embed "query + reasoning chain", the vector lands near documents that would help complete that reasoning.

**HuggingFace:** `facebook/ReasonIR-8B`

## Mira-Reasoning-Retrieval (Forward AI Labs, 2025-2026)

**BRIGHT Leaderboard #1:** 66.9 nDCG@10

### Full Training Pipeline

**Phase 1: Candidate Rewrite Mining**
- Use diverse LLMs (GPT-4, Claude, etc.) to generate multiple query rewrites
- For each rewrite, compute retrieval score (nDCG)
- Keep rewrites that significantly improve retrieval → training signal
- Result: (original_query, best_rewrites, retrieval_scores) dataset

**Phase 2: Cold Start Training**
- Train retriever on mined (query, rewrite, positive_doc, hard_neg) tuples
- Initializes model to understand reasoning-enhanced queries

**Phase 3: GRPO-Driven Intent Alignment**

GRPO (Group Relative Policy Optimization, from DeepSeek-R1):
- Generate group of candidate query expansions (like thinking "thoughts")
- Score each candidate by retrieval quality
- Reward = multi-dimensional score:
  1. **Retrieval reward:** nDCG improvement from using this expansion
  2. **Faithfulness reward:** expansion faithful to original query (no hallucination)  
  3. **Coverage reward:** expansion covers all aspects of query
  4. **Conciseness reward:** no verbose repetition

- Update model to prefer high-reward expansions

**Key innovation:** Treating query expansion as "thinking" and applying DeepSeek-R1 style RL to optimize it for retrieval.

### Gap Analysis: Mira (66.9) vs DIVER-RECOR (0.584)

Direct comparison not possible (different eval), but:
- Mira is single-turn BRIGHT; RECOR is multi-turn
- Multi-turn adds conversation management complexity
- If Mira approach applied to RECOR with H+R strategy, likely much higher than 0.584

## ConvSearch-R1: RL for Conversational Query Reformulation (EMNLP 2025)

**Paper:** "ConvSearch-R1: Reinforcement Learning for Conversational Search" 
- arXiv: 2505.15776
- Authors: Zhu, Wang, Feng, Song, Qiu (Fudan)

**Core idea:** RL specifically for conversational query reformulation:
1. **Warm-up:** Self-distillation (generate queries, retrieve, use retrieval signal to filter)
2. **RL phase:** reward = retrieval nDCG improvement
3. **No human annotations needed**

**Why different from Mira:**
- Mira: single-turn retrieval, RL on query expansion
- ConvSearch-R1: multi-turn conversational, RL on query reformulation
- More directly applicable to RECOR

**Results:** >10% improvement on TopiOCQA vs prior SOTA.

**Relevance to RETECO:** HIGH — if we had compute to fine-tune, this is the approach. Could train on RETECO dev set conversations (reverse: use test labels for few final turns, use rest for training).

## CoT in Query Generation: Inference-Time Methods

### Zero-shot CoT prompting (most practical for us)

Instead of `"Rewrite the query: {history} {turn}"`, use:

```python
prompt = """You are helping retrieve documents for a multi-turn conversation.

Conversation history:
{history}

Current question: {current_turn}

First, reason step by step about what information is needed to answer this question,
considering the conversation context. Then formulate a search query.

Format:
Reasoning: <step-by-step reasoning about what information is needed>
Search query: <the search query>"""
```

This implements the RECOR "History+Reasoning" strategy with zero additional training.

**Expected gain:** Based on RECOR Table 3, moving from pure QR strategy to H+R:
- BM25: .288 → .489 (+70%)
- E5-Instruct: .272 → .429 (+58%)
- Average: .322 → .479 (+49%)

### Chain-of-thought prompts for specific domains

**Biology/Science domains (high ceiling .73):**
```
"Consider the scientific mechanisms and processes relevant to: {question}
What underlying principles, phenomena, or biological processes would a relevant passage discuss?"
```

**Technical domains (lower ceiling .45-.50):**
```
"Consider the technical specifications, procedures, and components related to: {question}
What technical terms, procedures, or specifications would a relevant passage contain?"
```

**Law domain:**
```
"Consider the legal principles, statutes, and precedents relevant to: {question}
What specific legal doctrine, case precedent, or statutory provision would answer this?"
```
